SECTION B — RECOMMENDED CATALOGUES
==================================

SCOPEY RECOMMENDED ASTRONOMY CATALOGUES

1. GAIA DR3 — MAIN STAR CATALOGUE

Purpose:
Provides accurate stellar data for stars Scopey can identify, locate, and describe.

Recommended fields:
- Gaia source ID
- Common star name, when available
- Right ascension (RA)
- Declination (Dec)
- Apparent magnitude
- Parallax
- Proper motion in RA
- Proper motion in Dec
- Color information
- Distance in parsecs/light-years when reliable

Uses:
- What star am I pointing at?
- How far away is this star?
- What bright stars are visible tonight?
- What stars are near this target?

Important:
Do not put the entire Gaia DR3 catalogue on the phone. Use a filtered subset of useful/bright stars.

Official source:
ESA Gaia Archive
https://gea.esac.esa.int/archive/


2. MESSIER CATALOGUE

Purpose:
Provides 110 famous deep-sky objects that are especially useful for amateur astronomers.

Includes:
- Galaxies
- Nebulae
- Open clusters
- Globular clusters
- Other prominent deep-sky objects

Recommended fields:
- Messier number
- Common name
- Object type
- RA
- Dec
- Apparent magnitude
- Surface brightness, when available
- Angular size
- Distance
- Constellation

Examples:
- M31 — Andromeda Galaxy
- M42 — Orion Nebula
- M45 — Pleiades
- M51 — Whirlpool Galaxy
- M57 — Ring Nebula


3. NGC — NEW GENERAL CATALOGUE

Purpose:
Expands Scopey far beyond the Messier catalogue.

Recommended fields:
- NGC number
- Common name, when available
- Object type
- RA
- Dec
- Apparent magnitude
- Surface brightness
- Major angular axis
- Minor angular axis
- Position angle
- Distance, when available
- Constellation

Uses:
- Finding galaxies, nebulae, and clusters
- Target recommendations
- Identifying what the telescope is pointing toward


4. IC — INDEX CATALOGUE

Purpose:
Adds additional deep-sky objects beyond the NGC.

Recommended fields:
- IC number
- Common name
- Object type
- RA
- Dec
- Apparent magnitude
- Surface brightness
- Angular dimensions
- Distance, when available
- Constellation

For an early Scopey version, selected useful IC objects are enough.


5. IAU CONSTELLATION DATA

Purpose:
Allows Scopey to determine which constellation contains a coordinate or object.

Store:
- All 88 official IAU constellations
- Official name
- IAU abbreviation
- Boundary coordinates
- Optional traditional constellation line data
- Major named stars

Uses:
- What constellation am I pointing at?
- What constellation is Jupiter in?
- Show me Orion.
- What objects are in Sagittarius?


6. OPTIONAL DOUBLE/MULTIPLE STAR CATALOGUE

Purpose:
Provides information about binary and multiple-star systems.

Possible fields:
- Star/system name
- RA
- Dec
- Component names
- Magnitudes
- Angular separation
- Position angle
- Distance

Priority:
Optional for Scopey V1.


7. OPTIONAL VARIABLE STAR CATALOGUE

Purpose:
Allows Scopey to identify and explain stars whose brightness changes over time.

Possible fields:
- Name
- RA
- Dec
- Variable type
- Magnitude range
- Period

Priority:
Optional for Scopey V1.


RECOMMENDED SCOPEY V1 DATABASE

STARS:
- Approximately 5,000–20,000 useful/bright stars selected from a reliable stellar catalogue such as Gaia

DEEP-SKY:
- All 110 Messier objects
- Selected useful NGC objects
- Selected useful IC objects

CONSTELLATIONS:
- All 88 IAU constellations

SOLAR SYSTEM:
- Do not treat the Sun, Moon, or planets as fixed catalogue objects.
- Calculate their positions dynamically using an astronomical ephemeris.

USER TELESCOPE DATA:
- Telescope type
- Aperture
- Focal length
- Mount type
- Tracking capability
- Eyepieces

LIVE DATA:
- User latitude/longitude
- Date/time
- Weather/observing conditions
- Phone orientation
- Telescope altitude/azimuth
- Calibration state


IMPORTANT DISTINCTION

CATALOGUES:
Used for stars, galaxies, nebulae, clusters, constellations, and other mostly fixed celestial objects.

EPHEMERIS:
Used for moving Solar System objects such as:
- Sun
- Moon
- Mercury
- Venus
- Mars
- Jupiter
- Saturn
- Uranus
- Neptune

Do not store a single permanent RA/Dec coordinate for moving Solar System objects.


MINIMUM RECOMMENDATION

For Scopey V1, prioritize:
1. Filtered Gaia star data
2. Messier catalogue
3. NGC catalogue/subset
4. IC catalogue/subset
5. All 88 IAU constellation boundaries
6. A reliable Solar System ephemeris engine

This is enough catalogue coverage for a strong amateur-telescope application without storing an unnecessarily huge database on the user's device.


======================================================================
SCOPEY CALCULATIONS, EPHEMERIS, TELESCOPE, AND LIVE-DATA REQUIREMENTS
======================================================================

IMPORTANT:
Preserve the original coordinate data above. Static star/deep-sky coordinates
come from catalogues. The Sun, Moon, and planets must be calculated dynamically
for the requested date/time rather than assigned one permanent RA/Dec.

----------------------------------------------------------------------
1. MOON EPHEMERIS
----------------------------------------------------------------------

Inputs:
- UTC date/time
- User latitude
- User longitude
- User elevation (optional)

Outputs:
- Right ascension (RA)
- Declination (Dec)
- Altitude
- Azimuth
- Phase
- Illumination percentage
- Earth-Moon distance
- Angular diameter
- Moonrise
- Moonset
- Lunar transit
- Apparent brightness
- Angular separation from selected target

Mean Earth-Moon distance:
384,400 km

Mean synodic month:
29.530588853 days

Illuminated fraction:
k = (1 - cos(E)) / 2

where E is the Sun-Moon elongation.

Phase names:
- New Moon
- Waxing Crescent
- First Quarter
- Waxing Gibbous
- Full Moon
- Waning Gibbous
- Last Quarter
- Waning Crescent

Use a real lunar ephemeris for future positions. Do not generate future
RA/Dec merely by repeating the synodic month.

----------------------------------------------------------------------
2. SUN CALCULATIONS
----------------------------------------------------------------------

Inputs:
- UTC date/time
- Latitude
- Longitude

Outputs:
- Solar RA/Dec
- Solar altitude/azimuth
- Sunrise
- Sunset
- Solar noon
- Civil twilight
- Nautical twilight
- Astronomical twilight

Standard solar-altitude thresholds:
- Sunrise/sunset: approximately -0.833 degrees
- Civil twilight: -6 degrees
- Nautical twilight: -12 degrees
- Astronomical twilight: -18 degrees

If solarAltitude <= -18 degrees:
    astronomicalDarkness = true

----------------------------------------------------------------------
3. PLANET EPHEMERIS
----------------------------------------------------------------------

Objects:
- Mercury
- Venus
- Mars
- Jupiter
- Saturn
- Uranus
- Neptune

For each planet calculate:
- RA/Dec
- Altitude/azimuth
- Rise
- Set
- Transit
- Maximum altitude
- Earth distance
- Sun distance
- Apparent magnitude
- Angular diameter
- Phase angle where relevant
- Illuminated fraction where relevant

Planet coordinates must change with date/time.

----------------------------------------------------------------------
4. RA/DEC TO ALTITUDE/AZIMUTH
----------------------------------------------------------------------

Inputs:
- Object RA
- Object Dec
- UTC date/time
- Observer latitude
- Observer longitude

Calculate local sidereal time:
LST = GMST + longitude

Hour angle:
HA = LST - RA

Altitude:
Alt = asin(
    sin(Dec) * sin(Lat)
    + cos(Dec) * cos(Lat) * cos(HA)
)

Azimuth:
Az = atan2(
    -sin(HA),
    tan(Dec) * cos(Lat) - sin(Lat) * cos(HA)
)

Normalize:
Az = (Az + 360) % 360

Approximate direction mapping:
337.5-22.5 = North
22.5-67.5 = Northeast
67.5-112.5 = East
112.5-157.5 = Southeast
157.5-202.5 = South
202.5-247.5 = Southwest
247.5-292.5 = West
292.5-337.5 = Northwest

----------------------------------------------------------------------
5. ANGULAR SEPARATION
----------------------------------------------------------------------

For two celestial coordinates:

cos(d) =
sin(dec1) * sin(dec2)
+ cos(dec1) * cos(dec2) * cos(ra1-ra2)

d = acos(result)

Uses:
- Moon-to-target separation
- Object-to-object angular separation
- Conjunction detection
- Finding nearby objects

This is angular separation, not physical distance.

----------------------------------------------------------------------
6. TRUE STELLAR DISTANCE
----------------------------------------------------------------------

If parallax is in arcseconds:
distanceParsecs = 1 / parallaxArcseconds

If parallax is in milliarcseconds:
distanceParsecs = 1000 / parallaxMas

Convert parsecs to light-years:
distanceLightYears = distanceParsecs * 3.26156

RA/Dec alone cannot provide true physical distance.

----------------------------------------------------------------------
7. DEEP-SKY CATALOGUE FIELDS
----------------------------------------------------------------------

For galaxies, nebulae, clusters, and other deep-sky objects, store when
available:

- ID
- Common name
- Catalogue name/number
- Object type
- RA
- Dec
- Apparent magnitude
- Surface brightness
- Angular width
- Angular height
- Position angle
- Distance
- Constellation

Recommended catalogues:
- Messier
- NGC
- IC

Recommended stellar catalogue:
- Filtered Gaia data for useful/bright stars

Constellations:
- All 88 IAU constellations
- Official names and abbreviations
- Boundary coordinates
- Optional line/star relationships

----------------------------------------------------------------------
8. TELESCOPE PROFILE
----------------------------------------------------------------------

Store:
- Telescope name/model
- Telescope type
- Aperture in mm
- Focal length in mm
- Mount type
- Tracking capability
- GoTo capability
- Push-to capability
- Eyepiece focal lengths
- Eyepiece apparent field of view
- Barlow lenses

Magnification:
magnification = telescopeFocalLength / eyepieceFocalLength

Rough maximum useful magnification:
maxMagnification ~= 2 * apertureMm

Focal ratio:
fRatio = focalLengthMm / apertureMm

Approximate true field of view:
trueFOV = eyepieceApparentFOV / magnification

----------------------------------------------------------------------
9. ENVIRONMENT / OBSERVING CONDITIONS
----------------------------------------------------------------------

Retrieve dynamically where possible:
- Cloud cover
- Humidity
- Temperature
- Wind
- Visibility
- Atmospheric seeing
- Transparency
- Light pollution
- Bortle class
- Sky brightness
- Moon altitude
- Moon illumination
- Moon-target angular separation

Bortle scale:
1 = exceptionally dark
2 = typical dark site
3 = rural sky
4 = rural/suburban transition
5 = suburban sky
6 = bright suburban
7 = suburban/urban transition
8 = city sky
9 = inner-city sky

Use actual light-pollution data for Bortle estimates rather than ordinary
weather or population alone.

----------------------------------------------------------------------
10. LIVE ORIENTATION
----------------------------------------------------------------------

Phone data:
- Accelerometer
- Gyroscope
- Magnetometer/compass
- Device orientation
- Compass heading

Telescope data:
- Current altitude
- Current azimuth

Calibration data:
- Calibration state
- Altitude offset
- Azimuth offset
- Sensor accuracy/confidence

Shortest azimuth movement:
deltaAzimuth =
((targetAzimuth - telescopeAzimuth + 540) % 360) - 180

Altitude movement:
deltaAltitude = targetAltitude - telescopeAltitude

Example guidance:
- "Move 8 degrees upward and 12 degrees to the right."
- "You're getting closer."
- "Almost there."
- "Target aligned."

Example alignment thresholds:
- >10 degrees: FAR
- 3-10 degrees: GETTING CLOSER
- 0.5-3 degrees: ALMOST THERE
- <0.5 degrees: ALIGNED

----------------------------------------------------------------------
11. WHAT AM I POINTING AT?
----------------------------------------------------------------------

Use current telescope Alt/Az and compare it with calculated Alt/Az for
catalogue objects.

Find angular separation from the telescope pointing direction to candidate
objects.

Use telescope field of view and sensor/calibration uncertainty as tolerances.

Do not automatically claim that the nearest object is definitely being viewed.

Example:
"Your telescope is pointed very close to Saturn."

----------------------------------------------------------------------
12. OBJECT VISIBILITY
----------------------------------------------------------------------

Basic altitude categories:
- altitude <= 0: below horizon
- 0-15 degrees: very poor
- 15-30 degrees: low
- 30-60 degrees: good
- 60-90 degrees: excellent altitude

Final visibility should also consider:
- Apparent magnitude
- Surface brightness
- Telescope aperture
- Magnification/field of view
- Moon interference
- Cloud cover
- Transparency
- Seeing
- Light pollution
- Solar altitude/twilight

----------------------------------------------------------------------
13. MOON INTERFERENCE
----------------------------------------------------------------------

Inputs:
- Moon altitude
- Moon illumination
- Moon-target angular separation
- Target surface brightness
- Target type

General logic:
- Moon below horizon -> minimal lunar interference
- Bright Moon + above horizon + small target separation -> greater interference
- Diffuse galaxies/nebulae receive a larger penalty than bright planets/stars

----------------------------------------------------------------------
14. TARGET RECOMMENDATION
----------------------------------------------------------------------

Possible 100-point internal scoring model:
- Altitude: 0-30
- Brightness: 0-20
- Telescope suitability: 0-20
- Moon conditions: 0-10
- Sky darkness: 0-10
- Weather: 0-10

Use this to rank targets, but the chatbot does not need to expose the raw
score unless useful.

----------------------------------------------------------------------
15. RISE / SET / TRANSIT
----------------------------------------------------------------------

For each object determine:
- Next rise time
- Next transit time
- Next set time
- Maximum altitude

Handle:
- Objects that never rise
- Circumpolar objects that never set
- Objects below the horizon all night

----------------------------------------------------------------------
16. OBSERVING WINDOWS
----------------------------------------------------------------------

Combine:
- Solar altitude
- Target altitude
- Moon interference
- Weather
- Telescope capability

Return:
- Best start time
- Best end time
- Best time
- Quality/difficulty

----------------------------------------------------------------------
17. FUTURE DATE SUPPORT
----------------------------------------------------------------------

Support:
- Current time
- Tonight
- Tomorrow
- User-selected date/time
- At least five years of future dates

Do not store five years of hourly Moon/planet coordinates.
Calculate requested positions dynamically with an ephemeris.
